# Calendar Feed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `GET /calendar.ics` feed of upcoming episode air dates for watching entries, fed by an optional plugin schedule capability, cached and refreshed through the job queue.

**Architecture:** Contract (`Airing`, `ScheduleSource`, `SourceInfo.SupportsSchedule`) → anime plugin AniList mapping → migration 00014 cache (`item_schedules`, `airings`) → `sync_schedule` job → core ICS feed reading only the database.

**Tech Stack:** Go, SQLite (goose), html/template-free ICS writer, htmx not involved.

**Spec:** `docs/superpowers/specs/2026-11-10-calendar-design.md`

## Global Constraints

- No media words in core code/templates (`internal/guard`), including "episode": the contract says `Number`, the feed labels events from the kind's primary progress label.
- Migrations strictly increasing (next is **00014**); never edit applied SQL.
- Source errors follow the contract (rate limit/outage → retry, unusable answer → permanent).
- Everything through `scripts/go.sh`; full suite, `vet`, `fmt` before each commit; TDD; branch + `--no-ff` merge.

### Task 4: The feed

**Files:** create `internal/web/calendar.go`; route in `internal/web/server.go`; tests `internal/web/calendar_test.go`.

**Interfaces:** `GET /calendar.ics` → `text/calendar; charset=utf-8`. Builder: for each `ScheduleEntries` row whose manifest source declares `SupportsSchedule`, resolve the title (plugin title language + kind fallback) and emit a VEVENT for `AirsAt >= now-24h`: `UID <itemID>-<number>@allister`, `DTSTAMP` now (UTC), `DTSTART`/`DTEND` (30 min, UTC), `SUMMARY "<title> — <label> <number>"` (label from the kind's primary progress def, "Release" otherwise), `DESCRIPTION` "<source link label> <absolute item URL>" (request host, http). Calendar header: `VERSION:2.0`, `PRODID:-//Allister//Calendar//EN`, `CALSCALE:GREGORIAN`, `METHOD:PUBLISH`, `X-WR-CALNAME:Allister`. Writer: CRLF, 75-octet folding, escaping of `\ ; ,` and newlines. Side effect: enqueue `sync_schedule` for up to 20 `StaleSchedules` older than 12 h (best effort, logged).

- [ ] RED: the feed's content type; header/VEVENT structure; one event per stored airing; past airings filtered; inactive and non-capable sources absent; escaping and folding (a long title folds at 75 octets with CRLF); stale enqueues bounded at 20.
- [ ] Implement; route `GET /calendar.ics` (no auth, like the app).
- [ ] Full suite, vet, fmt; commit `feat: the calendar feed`.
