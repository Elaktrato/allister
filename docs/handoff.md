# Handoff (2026-11-11)

State of the project when the work moved from Claude Code to another agent. `main` contains everything below: the Games plugin with named source credentials for IGDB and Steam and the shared TMDB client, the statistics page, and the Yamtrack novel and manga imports; the owner pushes to `origin`.

## What exists

- **Core + plugins.** Generic core, anime as the first default plugin (AniList only), manga as an opt-in plugin (`DefaultEnabled: false`), books as another opt-in plugin with two kinds and three sources, and TV, movies and games as opt-in plugins, all togglable in Settings > Plugins. Plugin contract in `internal/plugin`, author guide in `docs/plugins.md`. Book and TV fixtures in `internal/plugin/plugintest` still prove the contract end to end.
- **Anime features.** Search (AniList), add, manual entries, edit details for every item, match-to-source by URL or dialog, local covers, genres and tags, recommendations (async fragment), Yamtrack CSV import (~830 rows, paced at 30 requests/min, resumable, unmatched allowed, 0.0 = unrated), per-plugin export, universal backup/restore (merge).
- **Manga features.** The same flow through a manga-typed AniList source: search, add, manual entries, edit details, matching, covers, genres/tags, staff credits, recommendations, AniList-account, MyAnimeList-XML and Yamtrack Manga CSV imports (the general Yamtrack export; `manga` rows that AniList does not report as `NOVEL`, resolved by MyAnimeList id; the real export gives 528 entries, 2 of them unmatched manual, plus the one `mangaupdates` row as manual), JSON export and backup. Two count progress tracks (chapters and volumes, chapter primary); no calendar because AniList has no chapter schedule. An optional **Magazine** field (serialization) comes from the official MyAnimeList API v2 with a MyAnimeList Client ID stored as a key field on the manga AniList source (`MAL_CLIENT_ID` fallback; the data is credited to MyAnimeList); it is fetched on add, match, import and "Update from source".
- **Books features.** Two kinds: **Book** (author, pages, year, publisher, ISBN, series, synopsis, dates, genres/tags; pages or percent) and **Light novel** (kind key `series`; volume and cumulative chapter, with both active by default and chapter-only or volume-only combinations). Sources: Open Library and Google Books for books, AniList for novels (`format: NOVEL`). Imports: Goodreads CSV (ISBN through Open Library then Google Books, no-ISBN rows manual) and AniList account (novels only, with optional repeat), and Yamtrack Novel CSV (the general Yamtrack export; `manga` rows AniList reports as `NOVEL` become Light novels, batch format lookup; the real export gives 11 imported from 539 manga rows, the rest ignored). JSON export, backup, no calendar. The source-kind declarations keep AniList to light novels and the book sources to books.
- **TV features.** One **Show** kind: season + episode + position (position cleared by +1), TVmaze primary with cast, genres and episode schedules, and TMDB (always declared, needs a key; no schedule). Yamtrack TV CSV import groups `tv`/`season`/`episode` rows into one show; episode-row presence/season progress is the watched data, blank episode statuses are accepted, and no-id shows stay manual. JSON export, backup, calendar events from TVmaze with season-aware labels.
- **Movies features.** One **Movie** kind: Want to watch / Watching / Paused / Seen / Dropped, an optional playback position (duration, no +1), year, runtime, director, studio, country, language, collection, release status, synopsis and release date, genres and tags. TMDB source: search, details, cast and director/writer credits, recommendations, TMDB and IMDb ids, cover. Yamtrack movie CSV import uses only movie rows, reports duplicates once, resolves numeric TMDB ids and keeps everything else manual with a note. IMDb CSV import (ratings and watchlist exports) and Letterboxd export ZIP import are described under Imports. JSON export, backup, no calendar (TMDB has release dates but no air times). Opt-in.
- **Games features.** One **Game** kind: Want to play / Playing / Paused / Played / Dropped, a **Playtime** duration track (no +1), platforms, developer, publisher, year, release date, IGDB's three completion-time estimates (main story, main + extras, completionist; minutes), genres, tags and summary. **IGDB** source (official API v4, Twitch Client ID + Secret, cached token with one refresh) supplies search, details, similar games, the Steam external-id lookup and best-effort time-to-beat; **Steam** source (official Web API for `GetOwnedGames`, plus the unofficial but stable store `storesearch`/`appdetails` endpoints) supplies the account library, playtime, search and metadata. Imports: Yamtrack game CSV (only game rows, statuses/scores/dates/comment/playtime kept, IGDB ids resolved, two duplicate pairs skipped so 1,019 rows become 1,017 entries) and Steam account by SteamID64 (one entry per owned game, Playtime, Planned when never played, resolved through IGDB then the Steam store; non-game tools stay manual). JSON export, backup, no calendar. Opt-in. GOG and HowLongToBeat are deliberately out (no official library API or export).
- **IMDb and Letterboxd imports.** The shared `internal/plugins/imdb` parser serves the TV and Movies plugins: ratings and watchlist CSV exports, columns read by name, English and German Title Type names, episodes and games ignored. A rated row becomes completed with its rating and Date Rated as the finish date; a watchlist row becomes planned. Rows resolve by IMDb id (movies: TMDB; TV: TVmaze, then TMDB). The Letterboxd export ZIP (movies) merges watched, diary, ratings, watchlist and reviews by name + year and resolves each film by exact title + year search on TMDB through the core `ResolveByTitle` capability; an ambiguous or missing match becomes an unmatched manual entry that keeps the Letterboxd link. The ZIP is streamed with memory caps.
- **Source API keys.** Settings > Plugins has an API keys card for every distinct keyed source of the installed manifests (enabled or not): save, replace or remove; a stored credential is never echoed. A single-key source uses `source.<source-id>.key` (TMDB, shared by TV and Movies; Steam). A multi-field source declares `KeyFields` and stores `source.<source-id>.<field>`: IGDB uses `client_id` and `client_secret`, all fields required, Remove clears every field. The credentials are read per request and passed to the plugins by the host; a failing read answers 500 everywhere (never "needs key"), and the fields of a source are saved in one transaction. `TMDB_API_KEY`, `IGDB_CLIENT_ID`/`IGDB_CLIENT_SECRET` and `STEAM_API_KEY` remain fallbacks. The Google Books key is optional (`KeyOptional`): it can be saved in the card, `GOOGLE_BOOKS_API_KEY` is the fallback, and the stored value wins; the MyAnimeList Client ID for the manga Magazine field is a key field on the manga AniList source, and the stored value wins. `plugin.ErrNotConfigured` gives actionable 503 messages, keyless imports keep manual rows and syncs keep stored credits.
- **Shared TMDB client.** `internal/plugins/tmdb` serves TV and Movies, resolving the key per request (v3 API key or v4 read token). Both manifests always declare TMDB; the key gates the calls, so there is no conditional manifest and no rebuild on save.
- **List UI.** Left sidebar navigation from the enabled plugins (Material Symbols icons, vendored and pinned), a **card view** (cover, title overlay, usable +1, colored status corner) that the list opens with by default, alongside the table view (sortable head, configurable columns); a view toggle in the header; search bar with a collapsible filter panel (filters generated from the manifest, any/all genres and tags with counts, URL-bookmarkable, live htmx updates), compact "Sort by" control, per-plugin **home settings** (default view and status), settings with their own tab column.
- **Per plugin settings** (`/settings/plugins/{id}`): title language (declared languages plus tags found in that plugin's stored titles; fallback order is plugin data via `KindDef.TitleFallback`) and visible table columns with order (`KindDef.Columns`, stored as `plugin.<id>.columns.<kind>`).
- **Appearance** (`/settings/appearance`, package `internal/appearance`): colour tokens as CSS custom properties from a generated, content-versioned `/appearance.css`; `tailwind.config.js` maps every colour class of the templates to a token through `internal/appearance/tailwind-map.json` (templates keep their slate/indigo classes; a test refuses unmapped ones). Presets plus an edited palette, system/bundled/uploaded fonts (table `fonts`, migration 00013, files in `DATA_DIR/fonts`), text size; included in the backup.
- **Imports.** Yamtrack CSV (the shared parser handles anime, TV, movies and games) and the generic queue/history on Settings > Import; AniList account (by username, with an optional daily/weekly repeat) and MyAnimeList XML export in each of the anime and manga plugins' Import sections, plus Yamtrack Manga CSV in the manga plugin; Goodreads CSV, AniList account and Yamtrack Novel CSV in the books plugin; Yamtrack TV CSV and IMDb CSV in the TV plugin; Yamtrack movie CSV, IMDb CSV and the Letterboxd export ZIP in the movies plugin; Yamtrack game CSV and the Steam account import (SteamID64) in the games plugin. Each has a rule for existing entries (skip / update when the source is newer / always update). The MAL XML, Goodreads and Yamtrack TV exports have no timestamps, so "newer" never updates there. Import resolution can fall back to a second source on `ErrNotFound`; a source that needs its credential configured (`ErrNotConfigured`) is handled the same way, so the row falls back or stays manual. Rows without an external id can become manual entries.
- **Calendar.** `GET /calendar.ics` serves an iCalendar feed for local subscribers: timed events for the upcoming releases of watching entries, from stored schedules (the optional `ScheduleSource` plugin capability, implemented by the anime plugin via AniList air dates; refreshed by the `sync_schedule` job, at most daily through the feed). Manga has no chapter schedule (AniList has none), books have no release-schedule source, games have no release schedule, and movies have release dates but no air times. TV uses TVmaze episode air times; the calendar carries a season and labels a release `Season 2, Episode 5`. TMDB shows have no events because TMDB has no air time.
- **Statistics.** `/stats` (the sidebar's Statistics entry) sums time, units, ratings and entry counts by completion date, for all enabled kinds or one kind, with period (all, year, 12m, custom), status, genre/tag (any/all) and `f.<field>` filters. Each kind declares `StatsDef` (`Time`, `Units`) as data; `internal/stats` aggregates, the web layer draws the SVG chart, rating distribution and 12-month activity heatmap. Time sources: anime (episodes × episode duration, a new `duration` field collected from AniList), TV (episodes × runtime), movies (runtime, position), games (playtime); manga and books count units only. Light novel (the book plugin's `series` kind) declares no stats and is deferred. The `entry_events` log (migration 00017, append-only, written in each entry change's transaction with origin `manual`, `import` or `restore`) feeds the heatmap; the heatmap counts only manual progress increases and completions, shows the last 365 days in UTC, and is narrowed by media only. The log is not backfilled: history before it is not reconstructed. The backup carries the newest 5,000 events per entry (`events_truncated` marks a cut log). "Update from source" on an overview (`POST /{plugin}/{source}/{id}/refresh`) fills only the fields an item lacks, one item at a time; there is no batch backfill. `StatsRows` loads at most 20,000 entries per request; above that the page shows a notice and no numbers.
- **Series groups.** A hand-built, ordered group of list entries of one plugin and kind (tables `series` and `series_parts`, migration 00018; an entry is in at most one series, positions are dense). Make an entry a series or add into one from search; the list has a Series tab and series badges, and a kind can declare a `SeriesHint` (fields that already carry a series name and number) used to suggest and to place a new part. The status of a series is derived from its parts. The backup writes a top-level `series` member after `items` (parts by item identity), and a merge restore applies it after all items (uid exists: skipped; missing or taken parts are left out and noted; no part left: not created; `Report.SeriesCreated`/`SeriesSkipped`). The JSON export carries `series` and `series_position` per entry.
- **Tracking depth (runs, notes, tags, lists).** Migration 00019 converts every entry into run 1 (next migration: 00020; `entry_runs`; `entries.display_run_id` is the run the list, filters, +1 and statistics treat as the entry's state: the latest run, except an abandoned repeat falls back to the latest completed one). Start again and the "<Action> instead?" question in the entry dialog, a read-only per-run timeline (`entry_events` with `run_id`), entry notes, run reviews and unit notes with a safe formatting renderer (bold, italic, lists, https links, `||spoiler||`), own tags (`ut`, `ut_all`, Settings > Tags) and custom lists (`/lists`) across plugins; statistics count every run; backup format 2 and JSON export version 2. See `docs/usage.md` and the design in `docs/superpowers/specs/2026-11-16-tracking-depth-design.md`.
- **Not planned for now.** MyDramaList (issue #2: no usable public API) and the Trakt and TV Time imports (issue #3: Trakt needs OAuth, TV Time has no stable export to build against) were closed; their notes stay in the issues. Series groups (above) answer issue #1; what stays out is listed under "Known follow-ups".
- **Builds.** Everything pinned and checksummed, see `PINS.md`.
- **CI and releases.** GitHub Actions (lint, govulncheck, tests, image smoke test and Trivy, gitleaks, CodeQL, dependency review, Scorecard, mutation tests on `main`/`dev`, Dependabot) and a tag-driven release workflow; every check runs locally with `scripts/ci.sh`. See `docs/ci.md`. The workflows have not run on GitHub yet (they start with the first push that contains them).

## Decisions worth knowing

- Migration 00007 dropped the first version's anime tables without copying (the only prior data was an empty preview). A volume from the first preview build starts empty after upgrading; the README warns about it. Migration 00011 moved the global `title_lang` setting to `plugin.anime.title_lang`. The movies and games work added no migration: source credentials use the existing settings table (`source.<source-id>.<field>`; the single-key field is `key`).
- Source credentials are plugin data only in the sense that a source declares `KeyLabel`/`KeyFields`; the values themselves are core settings with no manifest involvement. They are read per request, so saving in the UI takes effect without a restart, and the UI never renders them. They are not in the backup or a JSON export. Migration 00017 (`entry_events`, the statistics activity log) is a later one; 00018 is the series tables, 00019 converts every entry into run 1 (tracking depth) and the next is 00020. Migration 00008 stays unused.
- Progress combination switching (count/pages/percent) lives in the entry dialog, not in Edit details.
- Source "bad answer" errors map to a 502 page in the web (not retried), a failed row in imports.
- The universal backup contains everything including disabled plugins; there is no per-plugin selection screen (per-plugin export exists).
- The AniList client and the JSON exporter are shared packages (`internal/plugins/anilist`, `internal/plugins/jsonexport`); media-specific mapping stays in each plugin. Relation kinds are normalised (`source`, `adaptation`, `sequel`, `prequel`, `other`) and each plugin derives the related item's kind from the node's media type.
- The core now supports source-kind declarations, importer fallback sources, manual import rows with fields, all-id import dedupe and active-progress-only updates. The Google Books key is optional (card or `GOOGLE_BOOKS_API_KEY`); the source is quota-limited without it.
- Series groups (issue #1) are hand-built groups of existing entries in the core (a Series tab in every list, series badges, per-kind hints), not a separate volume model: a part is an ordinary entry with its own progress.
- Hiding the Progress column also hides the +1 button (documented, noted on the settings page).

## Known follow-ups (none blocking)

- **Not run in the tracking-depth session (no Docker):** golangci-lint, the Tailwind build with `internal/appearance/css-smoke.sh`, and `scripts/ci.sh all`. Run them before merging; only `go test` and gofmt were run.
- Deferred, minor, from the tracking-depth work:
  - Runs: DeleteRun/UpdateRun of a non-display run do not bump `entries.updated_at`; a NULL `display_run_id` gives a generic "no rows" error; `validateRunUpdate` duplicates `ValidateEntry`'s scalar rules; some coverage gaps (display run planned/paused, deleting run 1 of several).
  - Start again: `run_choice=new` is not one transaction (compensating delete leaves a status event; a concurrent removal gives 500, not 404); the raw-form finish>=start check precedes the merge; repeat-badge markup is duplicated in four templates; the latest-run form accepts any status by URL; the rating error text is duplicated and a start-run htmx error returns a full page.
  - Statistics: averages, "across N entries" and `KnownZeroTime` drift when past runs add time but not `TimeEntries`; `MissingTime`/`TimeEntries`/`UnitEntries` ignore past runs (undocumented); no StatsRows+Build seam test; the past-run progress query reloads the display run's progress.
  - Timeline: a removed track falls back to the raw key as a count, a nil `To` shows as 0, one unparseable `occurred_at` fails the fragment, and without JS it stays "Loading..." (no noscript link).
  - Formatting: spoilers lack screen-reader semantics (no role/aria-expanded, forced colours) and a click re-hides a revealed spoiler; links inside a hidden spoiler stay tabbable; a URL with parentheses is cut short; any "digits. " line becomes a list; the scanner is O(n^2) in the worst case (callers bound input); the fuzz scanner skips nesting; no committed JS test for the spoiler.
  - Unit notes: one above a lowered total cannot be edited or deleted, and "Add note" can 404 there; `maxUnit` duplicates `library.maxProgressValue` and a unit above 1e12 gives 422; the textarea `maxlength` counts UTF-16 units.
  - Own tags: `SetEntryTags` commits before `UpdateEntry`/`StartRun` (a 422 can leave tags saved); the tag filter shows whenever any tag exists; out-of-band option updates have no target on a page loaded without tags; `distinctTerms` (EqualFold) and `termKey` (ToLower) differ for rare letters; tags are fetched even when the column is hidden; htmx tag delete, merge 422 and multi-kind tag links are untested; the settings tab order differs from `settingsSections`.
  - Custom lists: add-from-search with a list and a series is not atomic and its notices differ; library search builds the whole list page for an htmx partial; the sidebar computes unused counts on every page; `SearchLibrary` applies LIMIT before the display-title sort; a duplicate-name race gives 500, not `ErrListExists`; `Items`/`Done` count rows of unknown kinds.
  - Backup and export: `ExportEntry` changed without a `ContractVersion` bump (noted in `docs/plugins.md`); backup reads items and lists outside one read transaction; list positions are not validated on restore and lists have no size cap; `ApplyImport` reads the past display run outside the write transaction; no web test for "new" on a past display run; the refusal message is worded differently in library and web.

- GitHub settings are applied (see the end of `docs/ci.md`); `main` and `dev` take changes only through pull requests with green CI. Later releases follow `docs/ci.md#releases` (`scripts/release-check.sh vX.Y.Z`).
- Deferred (statistics): book series have no time or units declaration (a series is flat: volumes and cumulative chapters, no per-volume items to time); manga and books have no time, only units; the heatmap has no history before the event log (no backfill, by design).
- Alias ids (issue #7, decided: canonicalize). When a source answers an unsaved item's Details with another valid id of its own (an IGDB slug resolving to the numeric id), the overview GET redirects to that canonical id and an add moves to it (or to the saved item that has it), like a match already stores the canonical id. Generic in `internal/web` (`canonicalAlias`); a saved item reached by an old alias keeps working.
- Not built (series): a per-volume chapter roll-up (a series shows completed parts, not summed chapters) and automatic grouping (the hint only suggests and orders; the owner makes the series). Not built: a Goodreads/StoryGraph/Calibre import beyond the Goodreads CSV, MyAnimeList as a live library source (deliberately skipped; only the optional manga Magazine field calls the MAL API v2, see docs/usage.md), other movie sources and imports (Trakt), GOG and HowLongToBeat (no official library API or export; deliberately out), dashboards, accounts.
- **Not built, by owner decision: a MangaDex manga release calendar.** MangaDex only knows chapters a scanlation group has already scheduled (usually none), and AniList manga would need a second schedule source in the core.
- **Not built, by owner decision: magazine release calendars.** There is no official schedule, feed or API for Weekly Shonen Jump or Shonen Jump+ (scraping Jump+ is ruled out by its terms), MANGA Plus has next-chapter dates only through an unofficial, undocumented API, and VIZ lists volumes only.
